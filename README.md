# Daily Interest Brief — PWA для iPhone

Лёгкая новостная сводка на HTML, CSS и JavaScript без внешних фреймворков, библиотек, шрифтов и сборки. Полный выпуск с подробными важными новостями сразу на странице, тёмная тема, фильтры по категориям, кнопка **Refresh**, установка на экран iPhone и чтение сохранённого выпуска без интернета. В выпуске одна или более важных новостей; фиксированного верхнего лимита количества нет.

Версия для ежедневной сводки: в `news.json` перенесён выпуск «Daily Interest Brief» от 9 ноября 2026 года из исходного чата. Это перенос существующего выпуска, без повторной проверки его фактов. Все исходные абзацы, списки, таблицы, выводы и ссылки отображаются сразу: отдельный блок «Полный выпуск» раскрывать не нужно. Внутренние изображения/виджеты ChatGPT не переносятся как картинки; доступны обычные ссылки на источники.

Основной текст берётся из `fullText` без сокращений. Он разделяется на полное вступление, все N подробных статей и заключение с выводами. Фильтры выбирают полные статьи по категориям; заключение остаётся доступным. Если заголовки выпуска имеют необычный формат и разделить его надёжно не получается, приложение выводит весь исходный текст целиком. Короткие карточки используются только у выпуска без `fullText`.

Основное внимание — важным событиям в **Macro**, **Pure Alpha**, **Shipping**, **Geopolitics** и **AI**; темы **EV/Porsche** и **NHL** также сохраняются. **Латвия** — обязательная область ежедневного мониторинга: политика, экономика, спорт и другие значимые события. Важные новости Латвии входят в общий полный выпуск; отдельный сюжет каждый день не обязателен, если значимых событий нет. Количество сюжетов определяется их значимостью: повторения и мелкие новости не добавляются ради объёма. В чате и приложении публикуется одна и та же подборка.

## Запуск на компьютере

1. Распакуйте архив и откройте терминал в папке, где находится `index.html`.
2. Запустите встроенный сервер Python 3:

   ```bash
   python3 -m http.server 8000 --bind 127.0.0.1
   ```

3. Откройте [http://localhost:8000](http://localhost:8000) в браузере.
4. Для остановки сервера нажмите `Ctrl+C` в терминале.

Открытие `index.html` двойным щелчком через `file://` не подходит: загрузка JSON и регистрация service worker требуют веб-сервера. На компьютере `http://localhost` допускается для разработки; для доступа с iPhone используйте опубликованный **HTTPS-адрес**. Обычный адрес компьютера в локальной сети по HTTP не даст полноценный офлайн-режим. [Требования Service Worker API](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API).

## Установка на iPhone

1. Опубликуйте папку одним из способов ниже.
2. Откройте её HTTPS-адрес в **Safari** и дождитесь загрузки выпуска.
3. Нажмите **Поделиться / Share**. В зависимости от расположения панели Safari эта команда может находиться внутри меню страницы.
4. Выберите **На экран «Домой» / Add to Home Screen**. Если пункта нет, найдите его через **Изменить действия / Edit Actions**.
5. Если показан переключатель **Open as Web App**, включите его; нажмите **Добавить / Add**.
6. Откройте новую иконку и один раз загрузите сводку с интернетом. Затем её сохранённая версия будет доступна офлайн.

Названия пунктов зависят от языка и версии iOS. [Инструкция Apple](https://support.apple.com/guide/iphone/iphea86e5236/ios).

## Публикация через GitHub Pages

1. Создайте репозиторий, например `daily-interest-brief`.
2. Добавьте **содержимое папки** в корень ветки `main`: `index.html` должен находиться сразу в корне репозитория.
3. Откройте **Settings → Pages → Build and deployment**.
4. Выберите **Source: Deploy from a branch**, ветку **main**, папку **/(root)** и нажмите **Save**.
5. Дождитесь успешной публикации. Используйте адрес, показанный в Pages; для обычного репозитория проекта он имеет вид `https://USERNAME.github.io/daily-interest-brief/`.

Ежедневные выпуски публикует существующая задача; читателю не требуется менять `news.json`. При ручном тестовом выпуске разработчик сохраняет изменение файла в той же ветке. Если папка размещена в `/docs`, выберите `/docs` как источник публикации. [Настройка источника GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Публикация через Cloudflare Pages

### Самый простой способ: Direct Upload

1. В Cloudflare откройте **Workers & Pages → Create application → Get started → Drag and drop your files**. В некоторых вариантах интерфейса сначала выбирается вкладка **Pages**.
2. Задайте имя проекта.
3. Перетащите распакованную папку с приложением. Убедитесь, что в корне загружаемых файлов находится `index.html`, а не ещё одна внешняя папка. Сборка не нужна.
4. Нажмите **Deploy site / Save and Deploy** и откройте выданный адрес `https://PROJECT.pages.dev`.
5. Для обновления выберите **Create a new deployment → Production** и загрузите обновлённую папку целиком.

Cloudflare также принимает ZIP с файлами сайта. Если архив содержит внешнюю папку `daily-interest-brief`, удобнее распаковать его и загрузить эту папку. Проект Direct Upload нельзя впоследствии переключить на Git integration — для неё создаётся новый проект. [Direct Upload: официальная инструкция](https://developers.cloudflare.com/pages/get-started/direct-upload/).

### Вариант: обновление из Git

В **Workers & Pages → Create application → Pages → Import an existing Git repository** подключите репозиторий. Выберите ветку `main`, пресет **None**, команду сборки `exit 0` и каталог результата `.` при размещении файлов в корне. Если приложение лежит в отдельной папке, укажите её как корневой каталог проекта. После публикации изменения выбранной ветки будут автоматически развёртываться. [Публикация статического HTML в Cloudflare Pages](https://developers.cloudflare.com/pages/framework-guides/deploy-anything/).

## Как обновляется сводка

Ежедневную публикацию выполняет существующая облачная задача **Daily Interest Brief** через подключённый GitHub. Её инструкция публикации описана в [PUBLISHING.md](./PUBLISHING.md). Задача готовит один выпуск для чата и сайта; приложение само новости не генерирует. Пользователю не нужно редактировать файлы или держать Mac включённым. API-ключи в сайт не добавляются.

Приложение проверяет новый JSON при открытии, возвращении на экран и каждые пять минут, пока оно видно. Повторные автоматические запросы выполняются не чаще раза в минуту. На закрытом iPhone ежедневная задача обновляет сервер; экран получает новый выпуск при следующем открытии. Для немедленной проверки доступна кнопка **Refresh**. Если свежий выпуск не поступил, отображается дата сохранённого выпуска и предупреждение о его давности.

### Формат данных — для разработчика

Для разработки и ручных тестов `news.json` редактируется в UTF-8 как корректный JSON: двойные кавычки, без комментариев и без запятой после последнего элемента. Это не требуется для обычного ежедневного чтения. Готовый файл из комплекта служит полным примером.

| Поле | Формат и назначение |
| --- | --- |
| `schemaVersion` | Обязательное число `1`, версия формата сводки |
| `demo` | `true` для демонстрации; `false` для реального проверенного выпуска |
| `date` | Дата выпуска `YYYY-MM-DD`, например `2026-11-09` |
| `updatedAt` | Момент подготовки с часовым поясом, например `2026-11-09T08:35:00+02:00` или `2026-11-09T06:35:00Z` |
| `fullText` | Основной полный текст того же выпуска в Markdown, до 100000 символов; исходные абзацы, заголовки, списки, таблицы, выводы и ссылки отображаются сразу |
| `headline` | Необязательная короткая строка о главной теме выпуска |
| `items` | Массив из **1 или более** важных новостей в порядке выпуска, без фиксированного верхнего лимита количества; `items.length` совпадает с числом новостей в `fullText` |
| `items[].id` | Уникальная непустая строка для каждой новости |
| `items[].categories` | Массив из одной или нескольких допустимых категорий |
| `items[].title` | Заголовок |
| `items[].summary` | Краткое содержание для резервных карточек, если `fullText` отсутствует |
| `items[].impact` | Значение новости для резервных карточек, если `fullText` отсутствует |
| `items[].source` | Необязательный объект `{"name":"Название источника","url":"https://…"}` либо `null`; ссылка должна вести на материал |

Восемь допустимых категорий: **Macro**, **Pure Alpha**, **Geopolitics**, **Shipping**, **EV/Porsche**, **AI**, **NHL**, **Latvia**. В JSON используется `Latvia`, а в интерфейсе фильтр называется **«Латвия»**. Регистр и написание значений JSON должны совпадать. Новость с несколькими категориями появляется в каждом соответствующем фильтре; в общей ленте она остаётся одной статьёй. При наличии `fullText` фильтр показывает подробный текст статьи, включая её выводы. Фильтр может быть пустым, если в выпуске нет значимых материалов этой категории. Изображения не обязательны и не используются: весь интерфейс сохраняется офлайн без внешних ресурсов.

В ежедневном выпуске заголовки новостей в `fullText` нумеруются последовательно **1..N** (например, `## 1. Заголовок`), без пропусков и повторов. Каждой новости соответствует один элемент `items` в том же порядке. Вступление, заключение, таблицы и календарь не считаются отдельными новостями; их полный текст сохраняется в `fullText`.

Время `updatedAt` показывается в часовом поясе **Europe/Riga** с учётом перехода на летнее время: указанный в JSON момент переводится во время Риги. Дата выпуска берётся отдельно из `date` и не сдвигается из-за часового пояса устройства.

После ручного изменения файла разработчик публикует тестовую версию; её можно загрузить кнопкой **Refresh**. Если новый файл некорректен или недоступен, приложение сохраняет возможность читать последнюю корректную сводку и показывает состояние загрузки.

## Офлайн и обновление приложения

Service worker сохраняет HTML, CSS, JavaScript, манифест, иконки и сводку. Для `news.json` сначала используется сеть; при её недоступности возвращается сохранённая копия с техническим заголовком `X-Brief-Cache: offline`. Дополнительно приложение хранит последнюю проверенную сводку в локальном хранилище браузера.

Кэш изолирован по адресу установки: разные проекты на одном домене не должны очищать данные друг друга. Ежедневная задача обновляет JSON без изменения версии приложения. При выпуске новых HTML/CSS/JS или иконок разработчик увеличивает `CACHE_VERSION` в `service-worker.js` и публикует файлы вместе; новая версия загружается при открытии приложения с интернетом.

Офлайн-режим требует хотя бы одного успешного посещения и завершённой установки service worker. Он сохраняет последний доступный выпуск, а не архив всех дней. Ссылки на внешние источники требуют интернета. Если iOS очистит данные сайта, пользователь удалит их вручную или браузер запретит хранилище, потребуется снова загрузить приложение онлайн.

## Короткая проверка после публикации — для разработчика

1. Откройте сайт: полный выпуск и дата видны сразу, включая исходные абзацы, списки, таблицы и выводы. В текущей версии это сводка из исходного чата, без отметки DEMO.
2. Переключите все категории; убедитесь, что показаны полные статьи, а заключение остаётся доступным. Вернитесь к общей ленте.
3. В тестовой копии измените абзац `fullText` в `news.json`, опубликуйте файл и нажмите **Refresh**: должен появиться новый текст. После проверки восстановите исходный выпуск.
4. После успешной загрузки отключите интернет и повторно откройте приложение: сохранённый выпуск должен оставаться доступным с отметкой состояния.
5. Проверьте установку через Safari на самом iPhone. Мобильный предпросмотр на компьютере не заменяет проверку установки на устройстве.

- Синтаксис трёх JavaScript-файлов и 20 сценариев проверки формата данных, включая неверные даты, повторяющиеся ID и недопустимые ссылки.

- Открытие приложения из подпапки `/daily-interest-brief/` во встроенном браузере; пять карточек, семь фильтров и окно инструкции установки.
- Макеты на ширине 320, 390 и 1024 пикселя: без горизонтального переполнения страницы.
- Refresh после изменения JSON; сохранение предыдущего выпуска при повреждённом JSON.
- Повторное открытие страницы с пятью карточками после полной остановки локального сервера.

Тестовые изменения JSON удалены после проверок. Установка на физическом iPhone не проверялась. Публикация GitHub Pages выполнена; Cloudflare используется только как альтернативный способ размещения.
