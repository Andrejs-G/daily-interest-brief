# Daily Interest Brief — публикация готового выпуска

Источник — существующая ежедневная задача ChatGPT «Daily Interest Brief». Один канонический выпуск используется для ответа в чате и этого приложения. Отдельная генерация новостей для сайта не нужна.

## Действия ежедневной задачи

1. Подготовить один выпуск по исходным редакционным инструкциям. Для повторного запуска в тот же день использовать уже подготовленный в этом чате полный выпуск за эту дату. Не подменять его другой подборкой.
2. Сформировать `news.json` в репозитории `Andrejs-G/daily-interest-brief`, ветка `main`. Получить текущую версию файла и её SHA через подключённый GitHub. При совпадении даты и полного текста повторный коммит не нужен. Более старым выпуском новый не заменять.
3. `fullText` — полный текст этого же выпуска в обычном Markdown: все пять новостей, вступление, таблицы, выводы и календарь. Сохранить формулировки и порядок. Ссылки на источники должны быть обычными абсолютными HTTP(S)-ссылками. Внутренние маркеры ссылок/виджетов ChatGPT не публиковать. Не придумывать адреса изображений; если есть доступная публичная ссылка, можно включить её как Markdown-ссылку на изображение. Приложение показывает такие ссылки без автоматической загрузки внешних изображений.
4. `items` — ровно пять карточек из того же выпуска. `title` совпадает с соответствующим заголовком; `summary` содержит дословный первый содержательный абзац, `impact` — дословный короткий абзац о значении или контексте. Карточки не заменяют полный текст.
5. Проверить JSON и требования ниже, затем обновить только `news.json` через GitHub с текущим SHA. При конфликте заново прочитать файл, сравнить дату/текст; не перезаписывать более новый выпуск. Не менять права доступа, другие репозитории или файлы приложения.
6. Вернуть в исходный чат тот же полный выпуск. Если публикация не удалась, доставить выпуск в чат и явно сообщить об ошибке публикации; не утверждать, что приложение обновлено.

## Формат

- `schemaVersion`: число `1`.
- `demo`: `false`.
- `date`: дата выпуска `YYYY-MM-DD`.
- `updatedAt`: время подготовки с часовым поясом, например `2026-11-09T08:35:00+03:00`. Для повторной публикации сохранять время исходного выпуска.
- `headline`: необязательный дословный анонс или его законченная часть, до 500 символов.
- `fullText`: непустой полный Markdown, до 100000 символов.
- `items`: ровно 5 объектов. Уникальный `id` до 100 символов; `title` до 250; непустые `summary` и `impact` до 3000 каждый.
- `items[].categories`: непустой массив без повторов из `Macro`, `Pure Alpha`, `Geopolitics`, `Shipping`, `EV/Porsche`, `AI`, `NHL`.
- `items[].source`: `null` или `{ "name": "Название", "url": "https://адрес-материала" }`. URL — реальная ссылка из источника, без данных входа; при отсутствии проверенного адреса использовать `null`.

Текущий `news.json` — полный рабочий пример. `feed.js` содержит проверку формата. Сохранить прочие поля допустимо, но не добавлять личные сообщения, настройки аккаунта, токены и содержимое других чатов. Публикуется только согласованная новостная сводка.

GitHub Pages публикует изменения ветки `main`; обновление может занять несколько минут. Приложение проверяет JSON при открытии/возвращении и раз в пять минут, пока видно на экране. Офлайн остаётся последний корректный выпуск с его настоящей датой.
